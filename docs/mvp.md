# Partyking MVP

產品定位與用詞見 [GLOSSARY.md](../GLOSSARY.md)。

## 已確定的決定

- **平台**:手機 App,第一版以本地為主。記錄與互掃交換完全離線。
- **帳號**:第一版不做登入頁面。在聚會碼上填自我介紹的賓客本來就不需要帳號,以保護隱私。
- **收費**:第一版不做課金與會員。日後只針對大型聚會收費。
- **技術**:React Native(Expo)做手機 App,加手機本地資料庫。
- **私人筆記**:身高、體型、重要度、記憶鉤子等只存在自己手機,永遠不上傳、不分享。
- **雲端**:Firebase(Firestore 加匿名登入),只作聚會名單的暫存中繼站,不長期保存使用者資料。自我介紹保存 7 天。
- **管理**:聚會碼的建立者自行管理名單,可以移除某位賓客。賓客之間不能舉報。
- **聚會名單**:先顯示暱稱、一句話介紹與自拍,點進去才看到本人勾選公開的欄位。
- **社交帳號**:預設全部關閉,每項由本人手動開啟。

## MVP 功能

1. **快速記錄**:身高滑桿、體型滑桿、重要度星星、記憶鉤子、選填名字(可只記片段)。記錄方式有兩種,可隨時切換:
   - **捏臉積木**:用髮型、眼鏡、膚色等積木拼出對方的樣子。
   - **熱度圓盤**:在圓盤上點一下,位置代表重要度與熟悉度。
2. **認識的人**:列表與搜尋。
3. **自我介紹**:本人填寫的表單,欄位多、全部可留空。
   - 基本:暱稱、一句話介紹、自拍
   - 做什麼:職業、公司或學校、正在做的事
   - 話題:興趣、最近迷什麼、想認識什麼樣的人
   - 輕鬆:星座、血型、最愛的食物
   - 社交帳號:Instagram、LINE、Facebook、Threads、X
4. **互掃交換**:兩人互掃 QR 碼,離線交換自我介紹。
5. **聚會碼**:建立者產生 QR 碼;賓客掃碼填表單並看到聚會名單;沒網路時先暫存本機,連線後送出。

## 不在 MVP 內

- 邀請與 RSVP(含時間、地點、服飾提醒)
- 夜店 / Bar 特化版本(上傳照片、場內分享)
- 婚禮禮金記錄
- 人與人之間的關係連線
- 加值備份與會員制度的細節

## 待決定

- 「新建紀錄日 / 局的類型」:開始一次新的紀錄前,先選這是什麼局(同學會、社團、迎新、過年等常用詞彙)。尚未設計,也還沒有進詞彙表。
- 大型聚會的收費方式與門檻(日後再談)。
- 雲端自我介紹的保存期限:先固定 7 天,是否延長視日後收費方案而定。
- 沒有登入時,賓客如何證明「這份介紹是我填的」以便日後修改或刪除(預設用手機上的隨機代號)。

## 目前進度

程式碼在 `app/`(Expo SDK 58、React Native、expo-router、expo-sqlite)。

- 五項 MVP 功能都已實作:快速記錄(捏臉積木、熱度圓盤可切換)、認識的人、自我介紹、互掃交換、聚會碼與名單。
- 另外做了 App 解鎖(密碼或生物辨識),對應「私人筆記要保護」的決定。
- 型別檢查、Android 打包、`expo-doctor` 都通過。**尚未在實體手機或模擬器上實測,雲端部分也尚未連上真實的 Firebase。**

### 聚會名單

- **雲端模式**(設定好 Firebase 後預設使用):賓客掃聚會碼就自動送出自我介紹,所有人即時看到名單。設定方式見 [cloud-setup.md](./cloud-setup.md)。
- **離線模式**(沒設定 Firebase、或建立時沒網路):名單由主辦人手機保管,賓客出示自己的 QR,由主辦人掃進名單。
- 雲端與本機的聚會、名單都在結束 7 天後自動刪除(`RETENTION_DAYS`、`CLOUD_RETENTION_DAYS`)。

### 打分(重要度)

- 以半顆星為單位(0.5 到 5 星,共 10 級),每級有顏色與文字標籤:路人、點頭之交、有印象、想再見、很重要。
- 在認識的人列表上直接點或左右拖星星就能改分,有觸覺回饋;點同一個分數或拖到最左邊清除。
- 列表可依 3 星以上、4 星以上、還沒打分篩選,並依分數排序。

### 已知限制

- QR 碼容量有限,自我介紹的自拍照不放進 QR,只存本機。
- 沒有登入,賓客身分是匿名登入的 uid;換手機或清除資料後無法修改先前送出的介紹。
- 雲端流程還沒用真的 Firebase 專案實測。

### 執行方式

```bash
cd app
npx expo start      # 用手機的 Expo Go 掃描;相機與 SQLite 在 Expo Go 內可用
```
